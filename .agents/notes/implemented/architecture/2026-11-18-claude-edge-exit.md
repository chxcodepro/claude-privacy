# Agent Note: Claude 进程的匿名同域出口核验

Status: implemented

## Problem

应用级 VPN 以及软路由的按目标分流可让 WebUI、第三方 IP 回显和 Claude 业务请求走不同出口。读取登录客户端会让探测接触用户凭证。另外，PJZ110 的 0.1.8 在重启后桥接已安装但 URI 授权缺失，Application.attach 报 `Unknown authority`，连核验页也未显示。

## Decision

承接[防火墙和桥接的双层门禁](2026-11-17-claude-privacy-gate.md)。Claude 1.261113.19 的 Production 环境配置为 `claude.ai`（APK 内 `ie1`）。Hook 在 Claude UID 下使用当前 Network 的 IPv4 DNS 与套接字，只给该域名的探测地址开放临时 443。独立的无 Cookie、无认证、无重定向 HTTPS 客户端发固定 GET，不继承登录客户端、设备值或账号数据；从响应读取严格校验的 `h`、`ip`、`loc`。白名单、CN 锁定、启动前防火墙和 IPv6 拒绝仍生效。

Hook 把见到的 IP、国家码和可离线确定的时区保存为一条本机观测。设置页面只刷新本机结果，不发起公网查询和不打开 Claude。新核验、网络变化或重启会清掉原观测；离开前台保留结果以便确认添加。首次没有实测记录时手动填入出口，避免为了自动初始化而放宽空白名单策略。

SukiSU 抢先锁定 Claude 后，等目标 Android 用户首次解锁再授予桥接 URI 可见性，短暂失败时重试。手动检查授权继续作为可达的恢复入口。只有新版 Hook 提交的 IP 与国家码同本地观测一致，脚本才允许放行。

## Alternatives considered

- 双第三方回显能交叉检查 IP，但分流时检查的是第三方域名的出口；用其中一个结果做地区查询还会额外传递真实 IP。
- 观察已登录的 Claude HTTP 客户端最接近业务请求，但存在凭证进入探测和路由审计的问题；首次门禁也要求在加载业务 Activity 前完成。
- 直接按 Cloudflare 机房推算时区看似完整，但机房不表示用户 IP 的时区。用国家唯一时区、本机已保存时区或预设，避免伪造检测结果。

## Consequences

同域同进程更接近应用实际出口；对按子域名、请求路径或传输协议分流的配置仍只说明该次探测的出口。显式 HTTP/SOCKS 代理暂保持锁定，避免透明直连。多时区国家无已保存值时用预设，界面不显示为实测地区时区。网络侧能看到连接本身的公网 IP，这正是核验输入；其余结果只落本地。新版的重启桥接和 VPN／软路由放行须在目标手机验收。
