# Agent Note: 按包名启用的语义接口适配

Status: implemented

## Problem

模块固定接受 Claude `26111319`，用户提供的新包实际为 `26111719`，并要求后续更新继续使用。新包的混淆已从无包短名改为多级短包名；仅去掉版本检查会让旧的 `ht0`、`fo0`、`s24` 等查找失败。新版 JADX 存在部分方法解码错误，关键匹配需要以原始 DEX 为依据。

## Decision

按 `com.anthropic.claude` 包名启用，删除固定版本号条件。读取当前 base/split APK 的 DEX，按稳定的序列化协议名称与字段键识别目标；在编码边界替换配置选择的字段，沿用现有开关、默认值、匿名 IP 核验及进程租约规则。字段索引经当前 descriptor 转换为语义键，避开混淆类名和字段名。

使用 Google 维护的纯 Java dexlib2 读取 DEX；每个进程扫描一次，按 DEX 分段读取，结果只保留类名。仅识别当前开启保护所需的接口；缺失或识别到多个目标时明确报错并保持联网锁定，避免配置显示开启却漏掉替换。未知 APK 版本自身不作为拒绝依据。

## Alternatives considered

- 只删除版本判断：改动最少，但新包已有混淆命名变化，实际 Hook 仍会失败。
- 按版本维护映射表：容易对具体样本验证，但每次重混淆仍要求发布更新，违背用户的持续使用要求。
- DexKit：原生查询性能优秀，但增加 JNI/ABI 加载路径；纯 Java 解析可同时在 Android 和主机上用真实 APK 验证，无需额外原生库。
- 自写 DEX 解析器：依赖少，但扩大二进制格式维护和校验负担，采用成熟解析库。

## Verification

- 旧、新两个实际 APK 均能识别同一组协议目标；发现机制不读取应用版本号。
- 编码替换覆盖厂商、机型、Android ID、运营商、Root/应用证据、电池、本机 IP、Plaid 语言/屏幕与 CCT 网络字段，原有关闭条件继续透传。
- 验证字段重排、混淆方法名、未选择字段透传及异常传播；只运行改动相关检查。
- 已构建 0.1.16 ZIP，配置结构与默认值沿用。当前手机未连接，进程内验证缺口保留。

## Consequences

未来新增采集协议或原生路径仍需审计。协议缺失、歧义和 Hook 安装状态写入诊断日志。编码阶段的替换契约错误保持向上传播，避免悄悄发送未替换的该载体。实际扫描时延和目标进程读回仍需手机验证。

旧、新样本识别结果与验证范围记录在 [验证记录](../../../../docs/VERIFICATION.md)。固定版本准入与混淆字段约定部分取代[原门禁设计](2026-11-17-claude-privacy-gate.md)；原门禁的 root 防火墙和桥接约定继续沿用。

若运行时替换契约失败，先收回联网并显示诊断提示；若 root 桥接也无法确认收回，则结束当前 Claude 进程，使该进程租约失效。该路径保留待真机检查项。

DEX 解析依赖为 Google Maven 发布的 [smali-dexlib2 3.0.10](https://dl.google.com/android/maven2/com/android/tools/smali/smali-dexlib2/maven-metadata.xml)，接口依据见 [smali](https://github.com/google/smali)。
