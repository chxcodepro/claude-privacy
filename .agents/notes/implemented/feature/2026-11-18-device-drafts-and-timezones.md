# Agent Note: 设备档案草稿与离线时区选择

Status: implemented

## Problem

设备和构建替身只能逐项填写，容易混出互不匹配的机型与指纹；手输时区需要记住完整的 IANA 名称。

## Decision

设备随机在一组有限的内置档案中选取，并生成以同一品牌、产品和设备代号开头的合成构建指纹。构建单独随机时沿用当前档案。两项均进入原有草稿，保存前不写配置，也不自动改开关。构建值保留 `{release}` 占位，Hook 仍按原规则填入系统版本。

时区选择器包含本地 IANA 列表及 UTC，过滤当前 WebView 无法格式化的选项，并保留已保存的有效别名。选项显示当前 UTC 偏移。更新列表时，以项目 Node 运行时的 `Intl.supportedValuesOf("timeZone")` 为基础，并检查与目标 Android tzdata 的交集。

## Alternatives considered

- 每次启动重随机：会让同一份配置前后不稳定，也缺少用户确认。生成只发生在编辑操作时。
- 运行时联网拿时区列表：内置列表足以支撑离线设置，也无需新权限或外部请求。

## Consequences

两项功能只改 WebUI，落盘的配置字段、默认值和 Hook 保持兼容。生成的构建指纹是合成值，不能据此识别官方固件。当前 UTC 偏移含夏令时变化。
