# Agent Note: 设置页的服务预检、时区预览与进程读回

Status: implemented

## Problem

在没有 Claude 实测时，IPv4 查询只显示一个地址。用户无法确认已访问的是 Claude 服务，也无法预览缺少城市级位置时将生效的时区。软路由节点失效时，一条笼统的网络失败提示也掩盖了连接阶段。

## Decision

沿用[匿名同域核验](../architecture/2026-11-18-claude-edge-exit.md)及[名单读回](../bug-fix/2026-11-18-ip-entry-state.md)。设置页的预检从固定的 HTTPS 请求读取回显主机、IPv4 和地区码；不复用账户连接、不发送选定 IP 去第三方。设置页将服务可达与应用放行分开显示，后者继续由 Claude 进程独立判定。

地区只有一个时区时用本机 ICU 数据推导，并与确认的 IPv4 一起保存；否则展示实际将使用的预设，不从 CDN 机房猜测位置。新版 Hook 在通过启动核验时读取当前生效的替身时区和语言，将匹配值附在 root 门禁观测上。离开前台后保留本次读回；下一次启动、换网或重启时按现有观测生命周期清理。

## Alternatives considered

- 在设置页直接替 Claude 放行：应用级 VPN 时可能看见不同的出口，且其他应用的网络成功只能说明服务可达。
- 为所有地址查询城市时区：需要向新服务提供选定的 IP 或维护额外的数据库。默认使用同一响应的地区码和可编辑预设。

## Consequences

发起时区查询无需登录或启动 Claude；提示中的预设仍是预览。时区和语言的读回反映目标进程的默认值，只在匹配当前设置时显示；SDK 或服务端的采集结果要单独验证。
