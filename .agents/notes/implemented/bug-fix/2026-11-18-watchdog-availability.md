# Agent Note: 出口守护补启动和过期保护

Status: implemented

## Problem

PJZ110 开机后有拦截链，却没有守护进程；实际启动失败被误写成网络故障。手动启动后在 ADB 看到守护仍存活，Hook 的旧式存活检查仍失败。独立守护若被强杀也无法执行退出回调。

## Decision

扩展[按进程回收规则](2026-11-18-force-stop-lease.md)。boot 服务等包管理器可用后运行 root 监督进程，由它启动、等待并重启出口守护。Claude 核验仅等待真正就绪，不在短暂的 Hook root 调用里孵化守护；PJZ110 上后者复测时一度允许却未持续持锁。实际持有独占文件锁且已发布就绪标记才算运行；状态无需跨进程检查守护 PID。设置页按此结果显示状态，可启动监督服务并复查。

已通过核验的 IPv4 放行以及探测临时例外进入 8 秒 UTC 截止的 iptables 匹配，只有持锁守护在确认本次进程仍有效时才续租。守护重新启动时丢弃旧租约。正常离开、应用被清理时仍尝试立即收回；守护自身被强杀时由内核时间匹配截止。这个保护依赖系统时钟正常向前走。

ColorOS 的延迟强停实测仍可能清空桥接可见性；即使安装时开启包级可查询性，处于停止态的 Provider 也可能返回 `Unknown authority`。守护检测 Claude PID 变更后按需准备 Provider、发放定向的读取授权；Claude 冷启动仅对这一错误限时重试，正常业务代码仍在放行后进入。

## Alternatives considered

- 只在开机启动一次，或从 Hook 临时调用启动：守护退出时需要额外恢复，短命调用的子进程也不可靠。
- 继续按 PID 查询守护：无法分辨守护退出与调用者看不到它。
- 只加一个启动按钮：改善恢复入口，但没有退出回调的守护强杀仍会留下规则。

## Consequences

守护运行独立于 Claude 和管理页；只清掉应用时应用租约撤销，两者都结束时旧规则也会过期。需要目标内核支持 iptables time 匹配；规则安装失败时保持拒绝。

PJZ110 的独立网络命名空间实测：带截止时间的规则在截止前通过、截止后拒绝，无守护参与。隔离脚本覆盖单杀守护后被监督重拉、双杀后停止续租、手动启动不复用旧租约。
